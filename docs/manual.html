0개요 & 준비물

Arduino Nano 33 BLE Sense의 내장 센서를 브라우저 대시보드에서 실시간으로 보고, 기록하고, 파일로 내보내는 시스템입니다. USB와 BLE(무선) 중 상황에 맞는 쪽을 골라 씁니다.

무엇을 만드나

보드에 펌웨어를 한 번 올리면, 보드가 내장 센서(가속도·자이로·지자기·온습도·기압·조도·마이크)를 읽어 USB Serial과 BLE로 동시에 내보냅니다. PC에서는 프로그램 설치 없이 브라우저 대시보드(GitHub Pages)만 열면 됩니다 — 대시보드가 데이터를 받아 Chart.js 실시간 그래프로 그리고, 수집한 데이터를 CSV/XLSX로 저장합니다.

1Arduino IDE 준비

보드 패키지와 라이브러리를 설치합니다. 온습도·IMU 센서 칩이 리비전(Rev1/Rev2)에 따라 다르므로, 센서 라이브러리는 자기 보드에 맞는 쪽을 설치합니다.

1) 보드 패키지 — Arduino Mbed OS Nano Boards

  1. Arduino IDE 2.x 실행 → 왼쪽 보드 매니저(칩 아이콘) 클릭
  2. 검색창에 아래를 입력해 Arduino Mbed OS Nano Boards 설치
  3. 메뉴 도구 → 보드에서 Arduino Nano 33 BLE 선택
Arduino Mbed OS Nano Boards

2) 공통 라이브러리 — ArduinoBLE

왼쪽 라이브러리 매니저(책 아이콘)에서 검색해 설치합니다. BLE 통신에 필수입니다.

ArduinoBLE

3) 센서 라이브러리 — 리비전별로 다름

보드 리비전 구분법은 다음 패널(펌웨어 업로드)에 있습니다. 모르면 일단 Rev2 기준으로 설치해 보고, 컴파일·초기화가 실패하면 Rev1로 바꿉니다.

Rev1 — 온습도 HTS221, IMU LSM9DS1 탑재. 라이브러리 매니저에서 아래 4개를 각각 검색해 설치:

Arduino_HTS221
Arduino_LSM9DS1
Arduino_LPS22HB
Arduino_APDS9960

순서대로 온습도 · IMU · 기압 · 조도/근접용입니다. 마이크(PDM)는 보드 패키지에 포함되어 별도 설치가 없습니다.

Rev2 — 온습도 HS3003(라이브러리 HS300x), IMU BMI270+BMM150 탑재. 라이브러리 매니저에서 아래 4개를 각각 검색해 설치:

Arduino_HS300x
Arduino_BMI270_BMM150
Arduino_LPS22HB
Arduino_APDS9960

기압(LPS22HB)·조도(APDS9960)는 Rev1과 동일합니다. 마이크(PDM)는 보드 패키지에 포함되어 별도 설치가 없습니다.

💡 왜 라이브러리가 두 벌인가Nano 33 BLE Sense는 2023년경 Rev2로 개정되면서 온습도·IMU 칩이 바뀌었습니다. 칩이 다르면 드라이버(라이브러리)도 달라야 하므로, 이 프로젝트는 rev1용·rev2용 펌웨어를 따로 제공합니다. BLE 서비스 UUID는 두 펌웨어가 동일해서 대시보드는 리비전을 구분하지 않습니다.

2펌웨어 업로드

자기 보드 리비전에 맞는 .ino를 업로드하고, 부팅 메시지에서 DEVICE ID를 확인합니다. 이 ID가 BLE 연결의 열쇠입니다.

1) Rev1 / Rev2 — 어느 쪽인가

확인 방법Rev1Rev2
보드 실크(인쇄)·부품구형 — 온습도 HTS221, IMU LSM9DS1보드에 Rev2 표기 — HS3003, BMI270+BMM150
구매 시기(대략)~2023년 이전 구매분2023년 이후 구매분 대부분
모를 때한쪽 펌웨어를 올려보고 시리얼 모니터에 센서 초기화 실패가 뜨면 다른 쪽으로 교체

2) 업로드 절차

  1. 저장소의 firmware/ 폴더에서 자기 리비전 파일을 Arduino IDE로 엽니다.
    • Rev1 → nano33ble_dashboard_rev1.ino
    • Rev2 → nano33ble_dashboard_rev2.ino
  2. 보드를 USB로 연결 → 도구 → 포트에서 보드 포트 선택 (보드: Arduino Nano 33 BLE)
  3. 업로드(→) 클릭 → "업로드 완료" 확인
업로드가 안 될 때보드의 리셋 버튼을 빠르게 두 번 누르면 부트로더 모드(LED 천천히 깜빡임)로 들어갑니다. 이 상태에서 포트를 다시 선택하고 업로드하세요. 포트 자체가 안 보이면 케이블이 충전 전용인지 먼저 의심합니다.

3) 부팅 메시지에서 DEVICE ID 확인

업로드 후 시리얼 모니터(115200 baud)를 열면 부팅 메시지가 나옵니다.

# ═══════════════════════════════════
# Arduino Nano 33 BLE Sense Rev1 v2.1
# DEVICE ID : A3F7
# BLE 장치명: BLE-A3F7
# 대시보드 ID 입력란에 위 DEVICE ID를 입력하세요
# ═══════════════════════════════════
  • DEVICE ID(예: A3F7)는 nRF52840 칩에 공장 출하 시 각인된 FICR DEVICEID의 뒤 4자리(16진수)입니다 — 보드마다 다르고 바꿀 수 없어서, 여러 보드가 섞인 교실에서 자기 보드를 찾는 이름표가 됩니다.
  • BLE 장치명은 BLE-XXXX 형식으로 광고됩니다.
💡 스티커 한 장이면 시리얼 모니터가 필요 없어집니다확인한 DEVICE ID를 보드에 스티커로 붙여 두세요. 게다가 대시보드는 USB로 한 번 연결하면 부팅 메시지에서 ID를 자동 추출해 localStorage에 저장하므로, 이후에는 시리얼 모니터를 열 일이 없습니다.
✅ 이 패널의 완료 조건시리얼 모니터에 DEVICE ID가 표시되고, 센서 초기화 실패 메시지가 없으면 보드 준비 끝입니다. 시리얼 모니터를 닫고(포트 점유 해제) 다음 패널로 넘어가세요.

3대시보드 접속·연결

브라우저(Chrome/Edge)로 대시보드를 열고, USB 또는 BLE로 보드에 연결합니다.

1) 대시보드 접속 — 반드시 Pages 주소로

https://xparapx.github.io/Arduino_Nano33_BLE_SensorLab/dashboard.html
⚠️ 로컬 파일(file://)로 열면 BLE가 안 됩니다Web Bluetooth는 보안상 https(또는 localhost)에서만 동작합니다. 파일을 내려받아 더블클릭으로 열면 BLE 장치 선택창 자체가 뜨지 않으니, 위 GitHub Pages 주소로 접속하세요.

2) 연결 — USB 또는 BLE

  1. 보드를 USB로 PC에 연결 (Arduino IDE 시리얼 모니터는 닫아 둘 것 — 포트를 한쪽만 쓸 수 있음)
  2. 대시보드에서 통신 속도 115200 baud 확인 (기본값)
  3. 포트 연결 클릭 → 브라우저 팝업에서 보드 포트 선택
  4. 연결되면 부팅 메시지가 로그에 흐르고, # DEVICE ID : XXXX 줄에서 보드 ID를 확인할 수 있습니다

USB는 전원과 데이터를 함께 공급하므로 배터리가 필요 없고, 100Hz까지 안정적으로 수신됩니다.

  1. 먼저 USB로 한 번 연결 — 부팅 메시지에서 내 보드 고유 ID가 자동 추출되어 Bluetooth 버튼 아래에 내 보드: BLE-A3F7 뱃지로 표시됩니다 (새로고침 후에도 유지)
  2. 보드에 전원 공급 — USB 전원 또는 LiPo 3.7V 배터리(3.3V 이상 유지)
  3. Bluetooth 연결 클릭 → 선택창에서 뱃지와 같은 이름(BLE-XXXX)을 선택 — 여러 모둠이 함께 쓸 때 다른 모둠 보드와 혼동 주의. 다른 ID를 고르면 경고 확인창이 뜸
  4. ID를 아직 확인하지 않았다면 USB 연결 안내가 먼저 표시됩니다 ([그래도 목록에서 직접 선택]으로 건너뛸 수 있음)

무선 동작 시 보드를 PC에서 30cm 이내에 두고, 샘플레이트는 20Hz 이하를 권장합니다.

4수집·내보내기

보고 싶은 센서만 켜고, 샘플링 주기를 정한 뒤 수집을 시작합니다. 종료하면 CSV/XLSX로 저장합니다.

1) 센서 활성화 토글

사이드 패널의 센서 활성화에서 7종 센서(가속도·자이로·지자기·온습도·기압·조도·마이크)를 개별로 켜고 끕니다. 토글은 수집 대상을 정하는 것이고, 그래프는 워크스페이스에서 변수를 골라 구성합니다. 각 센서의 현재값은 목록 행에 실시간 표시됩니다.

2) 샘플레이트

모드선택지용도
실시간1 / 10 / 20 / 50 / 100 Hz진동·움직임 등 빠른 현상 (BLE는 20Hz 이하 권장)
롱텀 수집 간격1분 / 5분 / 10분 / 30분 / 1시간온도·기압 등 장시간 변화 관찰 (수집 후 파일저장)
⚠️ BLE에서 고속 샘플링은 무리BLE Characteristic은 전송량 제한이 있어(문자열 20바이트) 고속 전송에 불리합니다. 50~100Hz가 필요하면 USB로 연결하세요.

3) 수집 조건 (트리거) — 선택

  • ⏱ 시작 지연 — 체크하고 초를 입력하면 N초 후 자동으로 수집 시작 (준비 시간 확보)
  • ⏹ 자동 종료 — 체크하고 초를 입력하면 N초 후 자동으로 수집 종료 (동일 조건 반복 실험)

둘 다 끄면 "조건 없음 — 수동 제어"로, 버튼으로 직접 시작·종료합니다.

4) 수집 시작 → 종료

  1. 수집 시작 클릭 — 차트가 비워지고 0초부터 새로 그려지며, 수집 레코드 수와 경과 시간이 실시간 표시
  2. 실험 진행 (수집 시작 전에는 차트가 정지 상태이고, 각 센서 카드의 현재값 숫자만 계속 갱신됩니다 — MBL 관례)
  3. 수집 종료 클릭 — 차트는 마지막 상태로 정지·유지되어 아래 분석 도구의 대상이 됩니다

5) 내보내기 — CSV / XLSX

CSV메타 주석(수집 조건) + 데이터 행파이썬·간단 분석, 가벼운 파일
XLSX"수집 정보" 시트 + 센서별 시트 + "전체" 시트엑셀에서 바로 그래프·보고서
💡 내보내기 버튼이 회색이면수집된 데이터가 0건이라는 뜻입니다. 수집 시작→종료를 거친 뒤에 활성화됩니다. 페이지를 새로고침하면 수집 데이터가 사라지므로, 종료 즉시 내보내기를 습관화하세요.
ℹ️ 전역 내보내기 범위사이드 패널의 CSV/XLSX 버튼은 내보내기 시점에 켜져 있는 센서의 행만 포함합니다. 꺼진 센서의 기록이 있으면 제외 안내가 뜨고, 특정 차트의 데이터만 필요하면 아래 6)의 차트 우클릭 내보내기(토글 무관)를 쓰세요.

6) 그래프 워크스페이스 · 분석 도구

  • 그래프 구성 — 기본은 그래프 1개입니다. 하단 중앙 x축 칩(시간↔센서 변수), 좌측 세로 y축 칩으로 변수를 고르고, 헤더의 ⊕로 Y축 추가(우측 2번째 y축) 또는 그래프 영역 추가(최대 4개)를 할 수 있습니다. ✕로 영역 제거(마지막 1개는 보호).
  • 드래그 도킹 — 추가한 그래프의 헤더를 누른 채 드래그해 다른 그래프의 우측 절반에 놓으면 그 행이 1행 2열로 스냅됩니다. 밖으로 드래그하면 단독 행으로 복귀. 레이아웃은 새로고침 후에도 유지됩니다.
  • 영역 선택(사각 ROI) — 수집을 멈춘 뒤 차트에서 왼쪽 버튼으로 드래그하면 사각형 영역(x·y 범위)이 점선으로 하이라이트됩니다. 영역 안을 우클릭(터치는 길게 누르기)하면 메뉴: 영역 CSV/XLSX 내보내기 · 면적(적분, x구간 기준) · 영역 피팅 · 선택 해제. y범위 판정은 주(좌측) y축 기준입니다.
  • 시리즈 체크박스 — y축이 2개인 그래프 상단에서 시리즈를 끄면 곡선이 숨고(취소선), 피팅·적분·접선·내보내기에서도 제외됩니다.
  • 차트 우측 툴바 — 카드에 마우스를 올리면 나타납니다: 크기 최적화 · 접선(dy/dx) · 적분(∫y dx 사다리꼴) · 피팅(선형/2·3차 다항/지수/거듭제곱/사인 — 파라미터·R²·잔차 RMS).
  • 분석 결과는 카드 하단 접이식 "분석 결과" 행에 쌓이며 [복사]·[지우기]할 수 있습니다. 시리얼 모니터 높이는 상단 경계를 드래그해 조절(더블클릭 복귀)합니다.
⚠️ 영역 선택 한계차트 버퍼는 롤링(최근 구간만 유지)이라 화면에 보이는 구간만 드래그로 선택할 수 있습니다. 더 긴 구간이 필요하면 전역 CSV로 내보내 스프레드시트에서 분석하세요.

?개념 정리 (FAQ)

실습 중 자주 나오는 질문을 모았습니다. 수업 정리·발표 준비에 활용하세요.

Q1. Web Serial과 Web Bluetooth는 뭐가 다른가요?

둘 다 브라우저가 하드웨어에 직접 접속하게 해 주는 웹 API입니다. Web Serial은 USB 시리얼 포트(유선)를, Web Bluetooth는 BLE 장치(무선)를 다룹니다. 이 프로젝트의 대시보드는 두 API를 모두 구현해서, 프로그램 설치 없이 브라우저 하나로 유선·무선을 오갈 수 있습니다.

Q2. FICR DEVICEID가 뭔가요?

nRF52840 칩 내부의 FICR(Factory Information Configuration Registers)에 공장 출하 시 각인된 64bit 고유값입니다. 변경이 불가능하고 전 세계에서 유일하므로, 이 프로젝트는 그 뒤 4자리(16진수)를 장치명(BLE-A3F7)으로 사용합니다. 보드가 수십 대 섞인 교실에서 "내 보드"를 확실하게 구분하는 방법입니다.

Q3. 왜 Chrome/Edge에서만 되나요?

Web Serial·Web Bluetooth는 Chromium 계열 브라우저(Chrome, Edge)에서 구현된 API로, Safari·Firefox는 지원하지 않습니다. 브라우저가 하드웨어에 접근하는 기능이라 보안 요구도 엄격해서, Web Bluetooth는 https(또는 localhost)에서만 동작합니다 — 대시보드를 GitHub Pages로 호스팅하는 이유입니다.

Q4. Nano 33 BLE는 Wi-Fi가 안 되나요?

안 됩니다. 탑재된 nRF52840은 BLE 전용 칩으로 Wi-Fi 라디오가 없습니다. 대신 저전력 무선(BLE)에 최적화되어 배터리로 오래 동작하고, 다양한 내장 센서와 함께 "들고 다니는 무선 센서 노드" 실습에 알맞습니다.

Q5. BLE로 보내면 데이터가 잘리는 이유는?

이 펌웨어의 BLE Characteristic은 문자열 20바이트 단위로 값을 씁니다. BLE는 원래 작은 데이터를 자주 주고받는 방식이라, 한 줄이 20바이트를 넘으면 잘라서 보냅니다. 고속·대용량 수집이 목적이라면 USB Serial이 정답입니다.

Q6. dashboard.html과 dashboard_cdn_dev.html은 뭐가 다른가요?

기능은 같고 라이브러리를 싣는 방식이 다릅니다. dashboard.html은 Chart.js·SheetJS를 파일 안에 내장한 배포용(인터넷 없는 교실에서도 동작), dashboard_cdn_dev.html은 같은 라이브러리를 CDN에서 로드하는 가벼운 개발용(인터넷 필요)입니다. 평소 수정은 개발용에서 하고, 완성되면 배포용 단일 파일을 갱신합니다.

끝정리·마무리

실습을 끝낼 때 데이터와 장비를 정리하는 순서입니다. 1~2분이면 끝납니다.

1) 데이터 백업

  1. 수집 중이면 수집 종료 클릭
  2. CSV 또는 XLSX 내보내기 — 페이지를 새로고침하거나 닫으면 수집 데이터가 사라지므로 반드시 먼저 저장
  3. 저장된 파일을 과제 제출 폴더·클라우드 등으로 백업

2) 연결 해제·장비 정리

  1. 대시보드에서 연결 해제(USB 또는 BLE) 후 브라우저 탭 닫기
  2. USB 케이블·배터리 분리 — LiPo 배터리는 보드에서 분리해 보관
  3. 보드는 DEVICE ID 스티커가 보이게 정리함에 보관 (다음 실습에서 바로 자기 보드를 찾을 수 있음)
💡 다음에 다시 쓸 때펌웨어는 보드에 남아 있으므로 다시 올릴 필요가 없습니다. 대시보드 주소만 열고 연결하면 즉시 이어서 사용 가능합니다. 브라우저 localStorage에 보드 별명도 남아 있어 저장된 보드 칩 1클릭으로 재연결됩니다.
